## 1. 项目概述

### 1.1 背景
传统的待办事项应用依赖用户手动输入、分类和提醒，增加了认知负担。随着大语言模型（LLM）的发展，用户期望通过自然语言交互，让 AI 主动协助管理任务。

### 1.2 产品愿景
打造一款**懂上下文、能自主规划、可连接外部工具**的智能待办 Agent。它不仅是任务列表，更是用户的个人生产力中枢。

### 1.3 核心定位
**纯文本交互的智能任务管理助手**

## 2. 技术架构

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | Vue 3 + Vite | 响应式界面，支持 SSE 流式接收 |
| **后端** | Golang (Go 1.21+) | 高并发 API 服务 |
| **AI 框架** | Eino (ByteDance) | Go 语言原生 LLM 编排框架 |
| **大模型** | MiniMax (abab6.5s) | 纯文本模型，中文理解强 |
| **向量数据库** | Milvus | 语义搜索和记忆存储 |
| **关系数据库** | PostgreSQL | 任务数据持久化 |

## 3. 功能需求

### 3.1 核心交互模块

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 文本聊天窗口 | 类似微信/ChatGPT 的对话界面 | P0 |
| 流式回复 (SSE) | AI 回复需打字机效果展示 | P0 |
| 快捷指令 | 支持 `/list`, `/done`, `/help` 等命令 | P1 |

### 3.2 任务引擎 (AI Core)

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 意图识别 | 判断用户是想创建、查询、修改还是删除任务 | P0 |
| 实体提取 | 从文本提取 `title`, `due_date`, `priority`, `tags` | P0 |
| 任务拆解 | 针对复杂任务，调用 LLM 生成子任务列表 | P1 |
| 上下文记忆 | 记住上一轮对话提到的任务 | P1 |

### 3.3 数据管理

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 任务持久化 | 存入 PostgreSQL，支持状态流转 | P0 |
| 历史记录 | 保存聊天历史，用于向量检索记忆 | P0 |
| 向量同步 | 异步同步到 Milvus | P1 |

## 4. 用户故事

| ID | 角色 | 需求描述 | 验收标准 |
|----|------|---------|---------|
| US-01 | 用户 | 我想通过打字输入"明天下午 3 点开会"，自动创建任务 | 系统识别出时间"明天 15:00"，标题"开会"，并保存到列表 |
| US-02 | 用户 | 我想说"把刚才那个任务推迟到周五" | 系统能关联上下文，找到最近创建的任务并修改时间 |
| US-03 | 用户 | 我想输入"准备周报"，自动拆解为子任务 | 系统生成"收集数据"、"撰写内容"、"发送邮件"等子项 |
| US-04 | 用户 | 我想查看"今天的高优先级任务" | 系统筛选列表并返回结果 |
| US-05 | 用户 | 我想完成任务，输入"完成了开会" | 系统将该任务状态标记为 Done |

## 7. 风险评估

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|---------|
| LLM 解析错误 | 中 | 高 | 增加"确认环节"，AI 生成任务后让用户点击确认再保存 |
| 上下文超限 | 低 | 中 | 限制对话历史轮数，仅保留最近 10 轮 + 向量检索关键信息 |
| 成本超支 | 低 | 中 | 设置每日 Token 配额，监控 API 调用量 |
| Milvus 同步失败 | 低 | 中 | 异步同步，失败重试，记录状态 |

## 8. 验收标准

1. **解析准确率**：自然语言转结构化任务的字段提取准确率 > 85%
2. **响应速度**：90% 的用户指令在 2 秒内得到反馈
3. **拆解合理性**：任务拆解步骤需符合逻辑，用户采纳率 > 80%
4. **同步稳定性**：向量同步延迟 < 1 分钟，无数据丢失
